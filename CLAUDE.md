# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Downloads daily OHLCV history for 16 exchanges (NASDAQ, NYSE, NSE, BSE, LSE, EURONEXT, XETRA, TSE, HKEX, SSE, SZSE, TSX, ASX, KRX, SGX, SIX) via `yfinance` and writes CSVs for MetaStock import. Plain Python scripts, no package/build step, no linter config. Offline tests: `tests/test_sources.py` (stdlib unittest: Alpaca updater with a fake client, synthetic NSE build, Yahoo incremental logic, CLI, and the real Tk GUI driven with stubbed network) and `tests/test_web.py` (browser app over HTTP, `eod_config.ini` parsing, the Alpaca -> Yahoo fallback). `README.md` is the detailed user-facing manual.

A `venv/` exists in the project root. `market_data_daily/` (daily), `market_data_hourly/` (hourly), `market_data_alpaca/` (Alpaca US) and `.ticker_cache/` hold real downloaded data — don't delete them; use a separate `--output` dir for experiments.

### US data from Alpaca (survivorship-free; the preferred US source since 2026-11-09)
- `market_data_alpaca/` (git-ignored, ~10 GB): NASDAQ/NYSE daily bars 2016-2026 as traded with split/spin-off factors, 30-minute-built 1-hour bars (`hourly/`, `hourly60/` = hour-only), universe incl. delisted companies, Alpaca corporate actions, `meta_<EX>.csv`. Downloaded and maintained by the TranscriptExtract repo (`swingbt/data_fetch/alpaca_fetch.py`, keys in `.alpaca2.env` / `.alpaca3.env` here); data card `market_data_alpaca/README.md`. It was moved here from `TranscriptExtract/swingbt/cache/us_alpaca/` (a junction remains there).
- The copies the other projects read, in this repo's own file layout (written by TranscriptExtract's `py -m swingbt.data_fetch.alpaca_export`; each folder has a README): `market_data_daily/<EX>/alpaca/<EX>.<KEY>.csv` (same columns as `raw/`; splits and spin-offs adjusted, delisted companies included and cut at their delisting date; KEY = ticker, or `TICKER@YYYY-MM-DD` for an older company under a reused ticker), `market_data_daily/<EX>/alpaca_exits.csv` (what a holder received after each series' last bar: cash/stock merger value, 0 for a bankruptcy, else the last close). Hourly: there is no CSV copy; SwingTrader and TranscriptExtract's swingbt read `market_data_alpaca/hourly60/<EX>/<KEY>.pkl` directly (the `market_data_hourly/<EX>/alpaca_1h/` CSV copy, 4 GB, was deleted on 2026-11-10; `alpaca_export --what hourly` would write it again).
- **One copy only (user rule, 2026-11-10):** this repo holds the only copy of the market data used by the Python projects (TranscriptExtract, SwingTrader, TradeAgent, TradeBasedOnWorkbook read it here; their old copies were deleted). **Never delete `market_data_alpaca/`**: the hourly download took about 62 hours. The NSE `.bak` folders and the Yahoo-built `daily/` and `bhavcopy/` outputs of NSE, NASDAQ and NYSE were deleted the same day (the defaults write `*_official/` and `*_alpaca/`; `--nse-source yahoo` / `--us-source yahoo` rebuild them from `raw/` if ever needed).
- `eod_downloader.py --us-source alpaca` (the CLI default for NYSE/NASDAQ; every key incl. delisted) first runs `alpaca_us.update_exchange()` (unless `--skip-download`), then builds `daily_alpaca/`, `by_symbol_alpaca/`, `combined_alpaca/` and `bhavcopy_alpaca/`; it refuses `--price-basis raw` (the files are already adjusted). `rebuild_combined.py --raw-dir market_data_daily/NYSE/alpaca --out ...` also works. Consumers: TranscriptExtract's swingbt (reads `market_data_alpaca/` directly, NOT updated by this repo), SwingTrader (its US markets read `alpaca/`, `alpaca_1h/` and `alpaca_exits.csv`).
- `alpaca_us.py` extends `<EX>/alpaca/` from Alpaca (adjustment `split,spin-off`, keys from `.alpaca3.env`/`.alpaca2.env`; `.alpaca.env` is dead; free plan = no SIP data from the last 15 minutes, so request ends are capped). Each fetch starts at the second-to-last stored bar; a changed overlap close is applied as a rescale ONLY when Alpaca's corporate-actions list has a split (exact listed ratio, measured within 2%) or spin-off for the symbol. Otherwise, or when the overlap day is missing from Alpaca's current history (new security under the ticker, e.g. CDLR 2026-11-05), the file is skipped and logged. Name changes with old == new are CUSIP/name-only changes and must be ignored (treating them as renames deleted 6 files once, restored on 2026-11-10). Ticker handed to another company: old file -> `TICKER@<change date>`. Log: `<EX>/alpaca_updates.csv`. Not updated: `alpaca_exits.csv`, `alpaca_1h/`. Re-running TranscriptExtract's export overwrites `alpaca/` with its own (older) end date.

### NSE from official bhavcopies (`nse_bhavcopy.py`, the CLI default for NSE)
- `--nse-source bhavcopy` (default unless `--price-basis raw`): `nse_bhavcopy.update()` fetches missing day files into `NSE/official_cache/full/` (same cache as `nse_delisted.py`; `fetch_day(..., mark_holiday=False)` for days not safely past, so today's unpublished file is not stored as a holiday), NSE's corporate-actions API by quarter into `NSE/nse_ca/` (needs nseindia.com cookies; failure falls back to the cache; downloaded once and reused: `nse_ca/checked.json` holds the last ex-date asked for per quarter file, and the API is only called when `latest_trading_day()` of the day cache is newer, for just the new days plus `CA_OVERLAP_DAYS`, merged into the quarter JSON; no new trading day = no request; caches older than `checked.json` take the file mtime; `nse_bhavcopy.py --refresh-actions` refetches every quarter), then rebuilds `NSE/official/NSE.<SYM>.csv` for every symbol (~3,700 incl. delisted) back-adjusted to today's basis. Outputs go to `*_official/` folders. Skips the rebuild when `NSE/official_info/build_signature.json` matches (bump `BUILD_VERSION` after changing rules).
- Rules are ported from TranscriptExtract's `swingbt/nse_official.py` (validated there against Yahoo; this port reproduces its bars on 3,652 of 3,653 shared symbols). Optional inputs from this repo's NSE pipeline: `raw_delisted/stitch_report.csv` (renames; same-ISIN renames are also found inline), `corporate_actions.csv` (Yahoo-derived split steps, exit prices), `recon/demerger_check.csv`, `raw/` (Yahoo confirmation of unlisted capital changes). `nse_demergers.csv` parents are matched by the final symbol, so a renamed parent (TATAMOTORS -> TMPV) falls back to NSE's own demerger row with the actual ex-date drop.

### GUI and the sources
- Section 1 checkboxes `us_alpaca_var` / `nse_official_var` (settings keys `us_source_alpaca`, `nse_source_official`, default True; greyed out in hourly mode). `_run_download_worker` routes those exchanges to `_run_source()` -> `core.update_source()` (wanted = picked tickers or None for ALL) + `core.source_tickers()` -> `_build_outputs(src_dir=, suffix=)`; other exchanges keep the Yahoo path. Tests drive the window with `mainloop()` (worker threads post via `after()`, which fails with manual `update()` pumping).

### Yahoo incremental downloads
- `download_ticker()` refetches from the second-to-last cached bar; if that bar's close moved > `BASIS_TOL` (0.5%), the cache was written before a split and the whole history is downloaded again. Fresh rows win over cached ones on overlap (`keep="last"`). The stale-gap check measures from the day after the last cached bar. End dates are inclusive everywhere: `_yf_fetch()` passes end+1 day to Yahoo (whose end is exclusive) and a cache counts as covering the range once it reaches `_last_weekday(end)`, so a start == end run (the GUI default quick range 1D) fetches that day.

## Architecture

**`eod_downloader.py` is the core library *and* the CLI.** `eod_gui.py` and `rebuild_combined.py` both `import eod_downloader as core` and reuse its functions, so all files must stay in the same folder and changes to core function signatures affect the GUI.

Pipeline (`main()` → `_download_and_build()`):
1. **Ticker directory** — `fetch_ticker_directory()` auto-fetches only for `BULK_FETCHABLE_EXCHANGES` (NASDAQ/NYSE from Nasdaq Trader, NSE from its equity list, BSE from the latest daily bhavcopy). Other exchanges need `--ticker-file` or single `--ticker`. Index tickers (e.g. `^NSEI`) are added via `EXTRA_INDEX_TICKERS` / `_inject_extra_tickers()` on both the fresh-fetch and cached-read paths, so new indices appear without `--refresh-tickers`. Cached to `<output>/tickers.csv` (CLI) or `.ticker_cache/<ex>_tickers.csv` (GUI).
2. **Download** — `download_all()` runs `download_ticker()` in a `ThreadPoolExecutor` (default 10 workers) with a `cancel_event` and `progress_callback` (used by the GUI). Each ticker is cached to `raw/<EXCHANGE>.<TICKER>.csv`. Re-runs are resumable/incremental: fully-covered tickers return `"cached"`, tickers whose cache covers the start date only fetch the missing tail. Empty results write an empty marker file (`"no_data"`) so they aren't retried.
3. **Build** — `build_daily_csvs` / `build_per_symbol_csvs` / `build_combined_csv` read `raw/` and write `daily/`, `by_symbol/`, `combined/all_data.csv` per `--layout`. Only the tickers requested this run are included, not everything in `raw/`. `_format_output()` + `_write_csv()` handle formatting for every layout; `--metastock-ascii` (the default since 2026-11-10 in every CLI and the GUI; `--no-metastock-ascii` for the plain layout) means header `<TICKER>,<PER>,<DTYYYYMMDD>,<OPEN>,<HIGH>,<LOW>,<CLOSE>,<VOL>`, bare ticker (`^` stripped), `YYYYMMDD`, 4-dp prices, CRLF. Sort on Timestamps *before* formatting dates. `build_bhavcopy_files()` always runs (unless `--no-bhavcopy` / GUI checkbox) and merges into `<output>/<EX>/bhavcopy/<EX>_YYYYMMDD.csv`.
4. `report_data_quality()` flags tickers with suspiciously few rows. Steps 2–3 always run separately per exchange under `<output>/<EXCHANGE>/` (raw, daily, by_symbol, combined, bhavcopy); `--split-by-exchange` is a hidden no-op kept for old scripts.

### Hourly data (`hourly_downloader.py`)
Separate CLI + module (imported by the GUI as `hourly`) for 1h bars, NSE/NASDAQ/NYSE only. Yahoo serves only the last ~730 days of 1h bars; the `raw_1h/` cache is never trimmed and re-runs append, so history grows over time. Datetimes are exchange-local, tz stripped. Layout is per exchange: `<out>/<EX>/raw_1h/<EX>.<TICKER>.csv` (cache) and `<out>/<EX>/<EX>_YYYYMMDD_HHMM.csv` (all tickers for one bar, named by bar start time; existing files are merged by symbol, not overwritten). MetaStock mode writes `<TICKER>,<PER>,<DTYYYYMMDD>,<TIME>,...` with PER=60. GUI "Data interval: Hourly" greys out the daily-only layout/bhavcopy options and keeps a separate save location per interval (`output` / `output_hourly` in settings; defaults `market_data_daily` / `market_data_hourly`).

### NSE as-traded / delisted / corporate actions (backtesting)
`raw/` is Yahoo's split/bonus/rights-**adjusted** data. The NSE-only scripts below correct it from NSE's official bhavcopy; full usage is in README section 6.
- `reconcile_nse.py` (diagnostic), `nse_delisted.py` (downloads bhavcopies to `NSE/official_cache/full/`, writes as-traded `NSE/raw_delisted/` + `isin_map.csv`), `nse_factors.py` (`NSE/recon/scale_factors.csv`: `as_traded = yahoo × Factor`, volume ÷ Factor), `nse_stitch.py` (`raw_delisted/stitch_report.csv`, same-ISIN renames, `Stitch=Y/N`), `nse_corporate_actions.py` (`NSE/corporate_actions.csv`, validates the hand-edited `nse_mergers.csv`).
- `eod_downloader.py --price-basis raw [--include-delisted]` applies `price_basis.py` in `_load_raw_frames()`/`_apply_basis()`; output goes to `daily_raw/`, `by_symbol_raw/`, `combined_raw/`, `bhavcopy_raw/` so adjusted files are never overwritten. Raw-basis factors exist for NSE, NYSE and NASDAQ (`price_basis.FACTOR_EXCHANGES`); other exchanges are written unchanged with a warning. `--include-delisted` requires raw basis (delisted files are as-traded) and stitches `Stitch=Y` renames (`_stitch_map()`); official rows win over Yahoo on overlapping dates. Builders gained optional `price_basis` / `include_delisted` kwargs (GUI unaffected, defaults unchanged). `build_bhavcopy_files` merges by symbol, so delete `bhavcopy_raw/` before a rebuild if symbol names changed.
- `nse_import_workbook.py <xlsx>` (needs openpyxl) turns the hand-researched delistings/mergers workbook into `nse_renames.csv` (ISIN-changed symbol changes, extra input to `nse_stitch.py`; only those passing the gap/price checks are stitched, most fail because the stock was suspended through the change) and `nse_exit_info.csv` (delist route/date/exit price notes; rights-entitlement tickers become `rights_entitlement_end` events instead of `delist`). Order: import -> `nse_stitch.py` -> `nse_corporate_actions.py` -> `--price-basis raw --include-delisted` rebuild (move `daily_raw/` and `bhavcopy_raw/` aside first when symbol names change).
- `download_ticker()` / `download_ticker_hourly()` return `"stale"` (logged, `stale_tickers.txt`) when an incremental fetch is empty although the gap spans >=3 business days; the cache is left untouched.
- Demergers: hand-maintained `nse_demergers.csv` (Date=ex-date,Parent,Child,Ratio,Note) -> `demerger` events in `corporate_actions.csv` (the parent's coinciding `adjustment` row is dropped) and `NSE/recon/demerger_check.csv` (parent's biggest drop within +-10 trading days vs the drop the ratio predicts). Seed rows are from memory; the check is crude because the child's first close can come weeks after the ex-date.
- Mergers are events in `corporate_actions.csv`, never spliced (old and new trade concurrently). Seeded ratios in `nse_mergers.csv` are from memory; `recon/merger_check.csv` flags >5% disagreement with prices.
- Re-run `nse_factors.py` after new splits; factors are only as current as its last run.
- NSE hourly as-traded: `nse_hourly_factors.py` turns the daily `scale_factors.csv` steps into `market_data_hourly/NSE/recon/scale_factors.csv` after measuring the price jump across each step in `raw_1h/` (Yahoo's hourly feed is sometimes adjusted, sometimes as-traded, sometimes only partly: statuses applied / already_traded / partial / ambiguous in `recon/split_evidence.csv`). `hourly_downloader.py --price-basis raw` then writes `NSE/as_traded/`; it warns if the factor file is missing. Run order: `nse_factors.py` -> `nse_hourly_factors.py` -> hourly raw build.
- NYSE/NASDAQ as-traded (Yahoo-only, no official source): `us_factors.py` writes `<EX>/recon/scale_factors.csv` (same format as NSE, so `price_basis.py` is shared; US prices round to 4 dp, NSE to 2) plus `recon/split_evidence.csv` and `splits.json`. Each split is judged against the cached prices (jump ~ ratio => cache already as-traded, skip; no jump => apply); splits outside the cached date range are ignored. Hourly uses `raw_1h/` and `price_basis.apply_raw_basis(..., date_col="Datetime")`; `hourly_downloader.py --price-basis raw` writes `<EX>/as_traded/` (`hour_file_path(..., price_basis)`). Serial reverse splits give factors down to ~1e-12, so `us_factors.py` keeps 10 significant digits (rounding to 6 dp gave Factor=0 and crashed the volume cast). Re-run it after new splits or after re-downloading raw caches. Not adjusted: spin-offs, mergers, dividends.
- `update_us.py` is the one-command refresh for NYSE/NASDAQ (download -> `us_factors.py` -> `--price-basis raw` rebuild, daily and hourly; `--skip-download`, `--daily-only`, `--hourly-only`, `--include-delisted`). It shells out to the other scripts and stops on the first failure.
- `us_delisted_list.py` builds `<root>/<EX>/delisted_symbols.csv` from Alpha Vantage `LISTING_STATUS&state=delisted` (free key via `--api-key` / `ALPHAVANTAGE_API_KEY`, or `--input` a saved CSV; untested against the live API so far, covers roughly 2010 onward). Feed it to `us_factors.py --delisted-file "<root>/{ex}/delisted_symbols.csv"` (`{ex}` expands per exchange).
- US delisted: Yahoo has no delisted directory. `us_factors.py --delisted-file` downloads a user-supplied symbol list into the normal raw cache and registers the ones Yahoo served in `<EX>/delisted_tickers.csv`; `--include-delisted` (daily `_delisted_files()` / hourly) then adds them to raw-basis builds. `_stitch_map()` only runs for NSE.
- BSE as-traded / delisted (official bhavcopies, same layout as NSE): `bse_delisted.py` caches every day file in `BSE/bhavcopy_cache/` and writes `BSE/raw_delisted/BSE.<SYM>.csv` + `code_map.csv` for scrips with no trade in the last 30 days (keyed by scrip code; symbol = last ticker, else the code; dormant-but-listed scrips land there too). `bse_factors.py` compares `BSE/raw/` with the official closes -> `BSE/recon/scale_factors.csv` (reuses `nse_factors.derive_factors`; 99.98% of days within 0.5%). BSE is in `price_basis.FACTOR_EXCHANGES`, so `--price-basis raw [--include-delisted]` writes `BSE/daily_raw/` etc. Run order: `bse_delisted.py` -> `eod_downloader.py --exchanges BSE --bse-source bhavcopy` (builds `raw/`) -> `bse_factors.py` -> raw rebuild. No rename stitching or corporate-actions file for BSE yet; BSE bonds/NCDs/G-secs (scrip codes 8xxxxx/9xxxxx) are filtered out everywhere (`bse_bhavcopy.drop_debt`, ticker directory); ETF/fund units (5xxxxx) and rights entitlements (7xxxxx) are kept.
- Symbol collisions: the same ticker can exist on NSE and NYSE (INFY, HAL). Always group by the directory's `Exchange` column (done in `main()` and the GUI "ALL" branch), never by a `symbol → exchange` dict.

### Symbol conventions (easy to get wrong)
- `prefixed_symbol()` / `EXCHANGE_PREFIX`: `NSE.TCS` style — used for **raw cache filenames and the output Symbol column** only.
- `yf_download_symbol()` / `YF_TICKER_SUFFIX`: `TCS.NS` style — the **actual Yahoo request**; mandatory for all non-US exchanges. Index tickers (`^NSEI`) are never suffixed.
- The `Ticker` column inside raw CSVs is always the bare ticker.
- MetaStock ASCII output uses the bare ticker (no prefix).

### BSE specifics
- Yahoo's `.BO` data is patchy: `download_ticker()` falls back to the `.NS` listing when BSE data `_looks_sparse()`.
- `bse_bhavcopy.py` is an alternate BSE source (`--bse-source bhavcopy`, lazily imported inside `download_all()`): downloads BSE's official per-day bhavcopy files (UDiFF CSV from 2024-07-08, older `EQ<DDMMYY>_CSV.ZIP` before), caches them in `<output>/bhavcopy_cache/`, and stitches them into the same `raw/BSE.<TICKER>.csv` files. Split/bonus back-adjustment uses Yahoo's corporate actions (cached in `splits.json`), disable with `--no-split-adjust`; unexplained large gaps are only logged.

### GUI (`eod_gui.py`)
- `MarketDataGUI(tk.Tk)` runs downloads/ticker refreshes on daemon threads; results return to Tk via `self.after(0, ...)`, and logging goes through `QueueLogHandler` → polled queue. Never touch Tk widgets from worker threads.
- All modules log via the shared `logging.getLogger("market_dl")` logger, which is how core/bhavcopy messages reach the GUI log pane. yfinance's own logger is set to CRITICAL on purpose, because "possibly delisted" noise is expected for warrants and units. `start_file_logging()` also writes `<output>/logs/run_<timestamp>.log`.
- Settings persist in `.ticker_cache/gui_settings.json` (`_save_settings` / load counterpart) — add new controls there too.
